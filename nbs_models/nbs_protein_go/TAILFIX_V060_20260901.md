# LATENCE NBS v0.6.0 perfopt tail-fix

Release name: `latence_nbs_v060_perfopt_tailfix_20260901`

This hotfix applies on top of the v0.6.0 perfopt release.  It fixes a
weak-primary exhaustive queue boundary failure observed at step 2547/2549:

```text
selected=83/96, scanned=99, remaining=16
```

## Cause

After 2547 complete 96-anchor steps, a rank has 99 weak-primary rows left.
Those rows are the residue repeatedly deferred by the 32-query ontology/group
packing constraints.  Only 83 can coexist in the penultimate episode, while
16 must be handled by the final synchronized step.  The old code correctly
returned the 16 rows to the queue but incorrectly required the penultimate
episode to contain all 96 requested anchors.

Increasing `weak_focus_scan_limit` cannot fix this case because the sampler
already scanned all 99 remaining rows.

## Fix and preserved invariants

- A sub-96 block is accepted only when the sampler scanned the entire pending
  queue and selected at least one anchor.
- A scan stopped by `weak_focus_scan_limit` still raises.
- Zero forward progress still raises.
- The final loader step now asserts that the rank-owned queue is empty, so the
  `weak_primary_exhaustive` contract cannot silently degrade.
- Metadata records `weak_primary_requested_count` and
  `weak_primary_partial_block` for audit.
- Model architecture, loss, graph sampling, candidate retention, optimizer,
  scheduler and the resolved 2549 steps/rank are unchanged.

## Install

From the project root:

```bash
tar -xzf /path/to/latence_nbs_v060_perfopt_tailfix_20260901.tar.gz \
  --strip-components=1 -C "$PWD"
```

Run the focused regression tests:

```bash
/opt/conda/envs/pytorch2.4/bin/python -m pytest -q \
  nbs_models/nbs_protein_go/tests/test_hybrid_weak_focus_v054.py \
  nbs_models/nbs_protein_go/tests/test_ddp_episode_sharding_v04.py
```

Then restart formal training from a fresh output directory.  The failed run
did not complete epoch 1, so an epoch-boundary checkpoint normally does not
exist and it must not be treated as a resumable formal checkpoint.

Startup must still report:

```text
steps/rank=2549
optimizer_steps/epoch=2549
total_optimizer_steps=50980
```

At the end of epoch 1, confirm:

```text
weak_primary_anchor_eligible_coverage_rate=1.0
unique_weak_primary_anchor_protein_count=489222
```

The epoch-average `wpa` may be slightly below 96 because one tail block is
intentionally partial.  This is expected and does not reduce exhaustive
coverage.
